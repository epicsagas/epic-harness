## 2. 시장 분석

### 2.1 TAM / SAM / SOM

```
TAM (Total Addressable Market)
├── 글로벌 AI 코딩 어시스턴트 사용자 (2026 추정): ~1,200만 명
├── 시장 성장률: CAGR 32% (2024–2028)
└── 관련 시장 규모: AI 개발도구 ~$47B (2026)

SAM (Serviceable Addressable Market)
├── Claude Code + Cursor + Codex + Gemini CLI 활성 사용자: ~400만 명
├── 멀티 도구 사용 개발자 (프로 이상): ~80만 명
└── 플러그인/확장 설치 의향 보유자: ~30만 명

SOM (Serviceable Obtainable Market)
├── 초기 타겟 (12개월): 1,000–5,000 활성 설치
├── 성장기 (24개월): 10,000–50,000 활성 설치
└── 포착 조건: 마켓플레이스 가시성 + 커뮤니티 구축
```

### 2.2 시장 트렌드

| 트렌드 | 영향 | 관련성 |
|---------|------|--------|
| AI 코딩 도구 다변화 | 7개 도구 지원 = 강력한 차별화 | 🔴 매우 높음 |
| 에이전트 워크플로우 표준화 부재 | epic-harness의 6 커맨드가 디팩토 표준 가능성 | 🟡 높음 |
| 셀프-임프루빙 AI 시스템 | Ring 3 진화 엔진 = 시대 흐름 부합 | 🔴 매우 높음 |
| 코딩 에이전트의 메모리/컨텍스트 한계 | Unified Memory (SQLite + FTS5) = 실질적 페인포인트 해결 | 🔴 매우 높음 |
| 오픈소스 AI 도구 생태계 확장 | Apache 2.0 라이선스 = 채택 장벽 최소 | 🟡 높음 |

| 자동 스킬 트리거 | ✅ 9개 | ❌ | Rules | 없음 | 없음 |

| 설치 편의성 | ✅ 플러그인/brew/crates.io | 내장 | 내장 | pip | VS Code |

### 3.2 독점적 차별화 요소 (Moat)

1. **Ring 3 에볼루션 엔진**: 유일하게 사용자의 실패 패턴에서 스킬을 자동 생성. 경쟁사 없음.
2. **크로스 툴 데이터 공유**: `~/.harness/` 디렉토리 하나로 7개 도구의 메모리/스킬 공유.
3. **지능형 메모리 시스템**: 중요도 기반 복합 스코어링 + 그래프 트래버설. 단순 캐시와 차원이 다름.

## 4. SWOT 분석

### Strengths (강점)
- **Rust 바이너리**: 고성능, 단일 파일 배포, Node.js 의존 없음
- **12,000+ 줄의 성숙한 코드베이스**: 20+ 커밋의 활발한 개발
- **4-Ring 아키텍처**: 명확한 계층 분리 (오토파일럿/커맨드/스킬/진화)
- **풍부한 통합**: 7개 AI 코딩 도구 + MCP 서버
- **10개 언어 i18n**: 글로벌 진출 준비
- **보안**: 가드 룰, SQL 인젝션 방지, 커맨드 차단
- **지식 그래프**: SQLite + FTS5 + BFS 트래버설 + 자동 중요도

### Weaknesses (약점)
- **v0.1.x**: 프로덕션 안정성 입증 필요
- **플랫폼 의존성**: Claude Code 플러그인 생태계 변화에 취약
- **높은 학습 곡선**: 4-Ring 모델 이해에 시간 필요
- **문서화**: README는 상세하나 튜토리얼/온보딩 부족
- **테스트 커버리지**: 공개된 테스트 결과/커버리지 없음
- **단일 개발자**: 버스 팩터 = 1

### Opportunities (기회)
- **AI 코딩 도구 폭발적 성장**: 2024–2028 CAGR 32%
- **멀티 도구 사용자 증가**: Claude Code + Cursor 병행 사용 보편화
- **에이전트 오케스트레이션 표준 부재**: 6커맨드가 디팩토 가능
- **엔터프라이즈 수요**: 팀 단위 에이전트 관리 (/team 기능)
- **크로스 프로젝트 학습**: 조직 내 지식 공유 수요
- **MCP 생태계 초기**: harness-mem MCP 서버로 선점 기회

### Threats (위협)
- **플랫폼 API 변경**: Claude Code/Cursor 훅 시스템 변경 시 대응 비용
- **경쟁 심화**: Anthropic/OpenAI/GitHub이 유사 기능 내장 가능
- **오픈소스 경쟁**: 유사 오픈소스 프로젝트 등장 가능
- **AI 모델 진화**: 모델 자체 능력 향상으로 하네스 필요성 감소 가능
- **채택 장벽**: "또 다른 도구" 피로감

## 5. 타겟 고객 분석

### 5.1 페르소나

| 페르소나 | 설명 | 페인포인트 | epic-harness 가치 |
|----------|------|-----------|-------------------|
| **멀티툴 파워유저** | Claude Code + Cursor + Codex 병행 | 각 도구마다 설정/컨텍스트 분리 | 통합 메모리 + 일관된 워크플로우 |
| **테크 리드** | 팀의 AI 코딩 품질 관리 필요 | 일관된 코드 품질, 보안 검증 부족 | /check + 가드 룰 + 팀 에이전트 |
| **오픈소스 메인테이너** | PR 리뷰 + 품질 관리 부담 | 반복적 리뷰, 일관성 부족 | /ship + 자동 리뷰 + /check |
| **스타트업 CTO** | 적은 인력으로 높은 품질 필요 | 리소스 부족 vs 품질 요구 | 전체 파이프라인 자동화 |
| **AI 코딩 초보자** | 프롬프트 엔지니어링 미숙 | 무엇을 요청해야 할지 모름 | 6개 명령어로 단순화 |

```
1순위: 멀티툴 파워유저 (높은 NPS, 낮은 CAC)

3순위: 스타트업 CTO (빠른 채택, 바이럴)
```
